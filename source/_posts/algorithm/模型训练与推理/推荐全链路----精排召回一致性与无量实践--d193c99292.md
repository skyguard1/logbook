<div><h2>1 概述</h2><p>前面我们讲过，大型推荐系统通常会将整个推荐链路拆分为召回、粗排、精排和重排等多个环节，以达到推荐效果和计算算力之间的平衡。从召回、粗排到精排，模型的复杂度通常是逐渐增加的，这意味着排序相同数目的物品模型所需要的算力越来越多。所以尽管精排的排序结果最贴近用户兴趣，我们都无法将之应用于所有物品的排序。但一个物品最终要曝光给用户，还是需要在精排模型中能够胜出。这也就引出了我们前面讨论的粗排和精排模型的一致性。然而，召回模型的候选范围通常是全库的物品，粗排模型的候选范围只是召回的物品，在这种情况下召回模型能否也用之前的方法提高召回和精排的一致性，这就是本文所要探讨的问题。</p><p>为了回答上述问题，我们在多个真实业务上进行了实验，最终发现和精排保持高一致性的召回可以作为一路重要的召回，能够显著提升整体推荐效果。同时，我们还将精排模型蒸馏其它模型的范式沉淀到了ModelZoo中，可以很方便地实现精排模型蒸馏粗排/召回模型，或者是将复杂的精排模型蒸馏为较简单的模型。</p><h2>2 精排和召回联合建模</h2><p>在本节中，我们对精排模型和召回模型联合建模方式进行了分析，并在实际业务上验证了这种建模方式的效果</p><h3>2.1 Batch内负采样</h3><p>我们知道，召回模型和粗排模型通常都采用双塔结构，它们的线上流程也十分相似。不同之处在于，召回模型的负采样通常是面向全库物品的，而粗排模型只把曝光却未点击的样本当做负样本。如果直接使用精排的样本训练召回模型，可能会带来选择偏差。最佳的解决方法是在构造召回样本时执行特殊的负采样策略，保证召回模型离在线的数据分布是一致的。然而，本文的目标是让精排模型和召回模型联合训练，精排模型和召回模型共享一份样本，引入额外的负采样样本可能需要改造精排模型原有的训练逻辑。因此我们采用业界较为流行的负采样方法来减弱精排样本带来的选择偏差，即在同一个Batch中为用户选择负样本。</p><p>要模拟真正的随机负采样，通常需要较大的Batch size，这对底层框架也增加了负担。好在无量已经支持很大的Batch size，我们一般能够设置到1024左右。在离线实验时我们还发现，随机负采样可能会导致离线AUC虚高，也就是分类变得更加简单，但模型实际上的排序效果却没有提升。因此，我们设计了混合采样方式，每个用户采样其它用户的正样本作为难负样本，采样其它用户的负样本作为自己的简单负样本。这种方式能够让模型学会区分用户感兴趣的物品和热门物品，同时又减弱选择偏差的影响。</p><h3>2.2 User特征计算优化</h3><div>在线上打分阶段，一个batch包含一个用户的特征和多个物品的特征。通常的做法是将用户特征与物品特征逐一拼接，然后送入到网络中计算每个物品的概率。但如果网络比较复杂，或者用户特征的比例非常大，这种方式容易导致大量的重复计算。用户特征优化就是在用户特征与物品特征交互前，尽可能地优化用户特征的计算量。在无量框架中，整个优化流程可以用下图说明：
<center>

可以看到，我们只针对用户特征进行优化。由于每个batch只有一个用户特征，所以在生成sparse或dense嵌入时，我们实际上只需要embedding的第一行就可以了。这样矩阵运算就可以优化为向量运算。直到用户特征与物品特征不得不交互时，我们才把用户特征再次复制为batch size的维度。在生成embedding与特征交互这之间的运算，都能够得到优化。在无量上的实现细节与优化效果可以参考文档。</div><h3>2.3 精排和召回联合训练</h3><p>精排和召回的联合训练我们依然还是采取类似于精排和粗排联合训练的方式，但在细节上有一些不同，模型结构如下图所示：
<img alt="" loading="lazy" src="/logbook/images/algorithm/d4a00cb88433815e0c89.png"/>
和精排与粗排联合训练，精排与召回联合训练有如下几点不同：</p><ol><li>召回阶段获得多个塔的向量之后，还需要进行Batch内负采样，并在负采样样本上计算Loss。</li><li>精排模型特征不再直接给双塔模型使用。之所以去掉了特征迁移，主要有以下几点考虑：<ul><li>粗排或召回使用精排Embedding特征，会导致线上耗时增加，因为有大量的Embedding参数需要拉取。</li><li>特征迁移能够加快模型收敛速度，但收敛后效果提升不会特别明显。效果的提升取决于特征压缩比例（即Transfer MLP输出大小），但太大的输出大小也会导致模型复杂度提高。</li><li>双塔模型对精排特征进行迁移这个方式是与模型结构强相关的，难以做到统一化。因此为了实现统一的联合训练工具，我们舍弃了这一步。</li></ul></li></ol><p>在模型具体实现中，我们仍然在召回模型中使用较小的Embedding维度，以降低召回模型的复杂度。召回模型每个任务的Loss包括任务本身的Loss和知识蒸馏的Loss。</p><h3>2.4 线上效果</h3><p>我们在QQ音乐和视频业务都进行了业务尝试，取得了不错的效果。其中视频有效人均vv+4%，播放人均有效时长+0.27%，QQ音乐人均次数+4.6%，人均时长+6.1%。均已全量。</p><h2>3 基于ModelZoo快速实现知识蒸馏</h2><h3>3.1 蒸馏模型快速实现</h3><p>为了方便快速地实现精排模型和粗排/召回模型的联合训练，提高推荐链路的一致性，我们在ModelZoo中集成了对应工具。基于该工具，用户可以在已有精排模型中加入几行代码，同步训练蒸馏的精排模型或粗排/召回模型。</p><p>在精排模型中插入蒸馏模型的代码改造如下：</p><div>
<pre># 创建蒸馏模型，需要指定特征配置文件
from model_zoo.models import DistillDssmModel

distill_dssm_model = DistillDssmModel(
	from_config='feature.yml',  # 特征和参数配置文件
	config_section_name="dssm")  # 蒸馏配置在配置文件中的section名字

# 调用蒸馏模型，计算出Loss，无量Metrics和Dssm的向量
dssm_loss, dssm_metrics, dssm_vectors = distill_dssm_model(
	teacher_logits=teacher_logits,  # List类型，精排模型各任务的logits
	teacher_labels=teacher_labels,  # List类型，精排模型各任务的label
	teacher_weights=teacher_weights)  # List类型，精排模型各任务的weight，非必须</pre>
</div><p>通过上面几行代码，就可以同时训练一个双塔粗排/召回模型。如果要训练一个精排模型（降低模型复杂度），也非常容易，只需要修改上述代码为：</p><div>
<pre># 创建蒸馏模型，需要指定特征配置文件
from model_zoo.models import DistillCTRModel

distill_ctr_model = DistillCTRModel(
	from_config='feature.yml',  # 特征和参数配置文件
	config_section_name="ctr")  # 蒸馏配置在配置文件中的section名字

# 调用蒸馏模型，计算出Loss，无量Metrics和CTR的Logits
ctr_loss, ctr_metrics, ctr_logits = distill_ctr_model(
	teacher_logits=teacher_logits,  # List类型，精排模型各任务的logits
	teacher_labels=teacher_labels,  # List类型，精排模型各任务的label
	teacher_weights=teacher_weights)  # List类型，精排模型各任务的weight，非必须</pre>
</div><h3>3.2 蒸馏模型特征配置文件</h3><p>上述对精排模型的蒸馏都用到了特征配置文件"feature.yml"，其中配置了蒸馏模型使用哪些特征，以及模型的超参数。把特征配置与超参数配置独立出来，方便对模型代码进行调试，同时不会对已有精排模型造成太多入侵。以蒸馏DSSM双塔模型为例，它的配置文件示例如下：</p><div>
<pre>dssm:  # section名字，用来标识配置开始位置
	# 定义特征，包括user，context，item三类特征。每类特征又包括sparse，dense和varlen三个子类，分别表示类别型特征，数值型特征和序列型特征
	features:
		user:
			sparse:  # 返回embedding的维度是(? embed_size)
				city: {slot: 100}
				uid: {slot: 102}
			dense:  # 返回tensor的维度是(?, upper - lower + 1)
				score: {slot: 200, lower: 1, upper: 1}
			varlen:
				playlist: {slot: 1000, len: 20}  # 返回tensor维度是(?, 20, embed_size)
		item:
			sparse:
				vid: {slot: 103}
			varlen:
				taglist: {slot: 1001, len: -1}  # 未指定长度的话，返回的tensor维度是(?, ?, embed_size)

		share_embeddings:  # 可以指定多组特征共享embedding table
			share1: [vid, playlist]  # 物品id和用户观看列表共享embedding

		embed_size: 32  # 全局embedding_size，对sparse和varlen特征生效
		save_type: int8_float32  # 量化策略，不设置或不给值为不量化，int8_float32为int8量化

	# 任意的k-v形式自定义配置，这些配置会被读入到实例变量custom_configs中，以k-v形式存储
	# 用户可自定义任意格式，任意层次的配置
	custom:
		expert_hidden_sizes: [512, 256, 128]  # MMOE DNN专家参数
		expert_num: 4  # MMOE专家数
		hard_neg_num: 0  # 每个正样本的难负样本采样数
		easy_neg_num: 0  # 每个正样本的简单负样本采样数
		tower_hidden_sizes: [128, 64, 32]  # MMOE中每个任务对应Tower的参数
		task_names: ["task1", "task2"]  # 多任务名字
		task_loss_types: [logloss, mse]  # 多任务损失类型，支持logloss和mse
		distill_loss_type: [bce, mse]  # 每个任务蒸馏损失类型，支持bce和mse
		distill_tau: 1.0  # bce蒸馏损失中softmax的温度系数
		distill_weight: 0.8  # 每个任务蒸馏损失比例 0~1
		negative_sampling: [false, false]  # 每个任务是否需要负采样
		user_optimize: true  # 是否开启user特征计算优化</pre>
</div><p>搭配一个特征和参数配置文件，并在现有精排模型中插入几行代码，就能自动训练精排模型和蒸馏的CTR模型/粗排模型/召回模型。而且由于蒸馏的模型一般较小，资源的增加也不会显著。</p><h2>4 总结</h2><p>本文探讨了精排模型和召回模型的联合训练方式，并在两个真实业务上验证了这种联合训练方法的有效性。此外，本文还将任意模型的知识蒸馏方案沉淀到ModelZoo中，方便业务实现快速的多模型联合训练方案，提高推荐链路整体的一致性。</p><p>最后，感谢@ppan、@gracelyang、@hemingwei的指导帮助，感谢@aidenpan、@arvinhuang、@jiangxingyu的大力支持！</p></div>
