<div><h1>1. 大数据平台介绍</h1><h2>1.1 大数据发展史</h2><blockquote>的“三驾马车”开启了大数据时代，并为我们指明了大数据的发展方向。</blockquote><p>学习具体的技术之前，我们先把时光倒回到 2004 年年后， 三驾马车横空出世，业界为之一振，大家恍悟：原来还可以这么玩儿。要知道，那段时间为了提升数据处理能力，各大公司都聚焦于如何提高单机性能，而的思路是使用普通的机器，组成大规模集群，通过“分治”的思想将海量数据分发到各个机器上，再分别进行计算。</p><p>其后的 Hadoop、 Hadoop 分布式文件系统 HDFS 和大数据计算引擎 MapReduce ，都是基于的论文而来。</p><p>再往后， 发布了更易用的 Hive，支持 SQL 进行大数据计算，让那些只懂得 SQL 的人就可以进入大数据领域，进一步降低了门槛，从而迅速得到开发者和企业的追捧。</p><p>为了提高资源复用，将 MapReduce 执行引擎和资源调度分离开来，Yarn 诞生了，2012 年，Yarn 成为一个独立的项目开始运营，随后被各类大数据产品支持，成为大数据平台上最主流的资源调度系统。</p><p>大家知道，随着这些年的硬件发展，内存已经没有原来那么可贵了，因此，把数据放在内存中进行计算的 Spark 迅速崛起了，它比 MR 更快，一经推出就迅速取代了 MR 的位置。</p><p>再后来，为了充分应对实时场景，同 MR 和 Spark 这类批处理计算框架不同的，Storm、Flink、Spark Streaming 等流计算框架也相应诞生了。</p><p>下面是一些主要论文，感兴趣的同学可以读一下，别怕，越是经典的论文，越是写的通俗易懂：</p><div>

PySpark 开发</h1><h2>4.1 Python VS Scala</h2><p>Spark 开发最常用的两个技术栈就是 Python 和 Scala，前期做了一些调研来对比二者：</p><ul><li>易用性方面，Python 胜出，Scala 是具有灵活预发的复杂语言</li><li>Scala 性能更好，Python 做计算密集型任务建议用多进程代替多线程（GIL全局解释器锁的存在），但随着内核的增加，Scala性能优势逐渐减弱</li><li>Scala 静态语言，重构和理解会更容易；小型临时实验代码用 Python 可以更快实现，大型软件开发建议用 Scala</li><li>使用机器学习算法（例如回归、分类、聚类和决策树）时，Python 提供了更好的支持（周边库丰富），Scala， SparkMLib 机器学习库只有较少的 ML 算法</li><li>使用 Scala for Spark 可以访问 Spark 框架的最新功能，因为它们首先在 Scala 中可用，然后移植到 Python</li></ul><p>结合个人的编程经验，最终我们选择了  PySpark 作为开发技术栈。</p><h2>4.2 US 平台上的 PySpark 运行环境</h2><p>TDW 官方提供了一个默认的 PySpark 运行环境，包含了Numpy、Scipy、sklearn、TensorFlow 等常用的工具包，一般情况下可满足开发需要。
