<pre>import gym
import random
import numpy

N_BINS = [5, 5, 5, 5]
LEARNING_RATE=0.05
DISCOUNT_FACTOR=0.9
EPS = 0.3

MIN_VALUES = [-0.5,-2.0,-0.5,-3.0]
MAX_VALUES = [0.5,2.0,0.5,3.0]
BINS = [numpy.linspace(MIN_VALUES[i], MAX_VALUES[i], N_BINS[i]) for i in xrange(4)]

def discretize(obs):
    return tuple([int(numpy.digitize(obs[i], BINS[i])) for i in xrange(4)])

qv = {}


env = gym.make('CartPole-v0')
print(env.action_space)
print(env.observation_space)
an = env.action_space.n

def get(s, a):
    global qv
    if (s, a) not in qv:
        return 0
    return qv[(s, a)]

def update(s, a, s1, r):
    global qv
    nows = get(s, a)
    m0 = get(s1, 0)
    m1 = get(s1, 1)
    if m0 &lt; m1:
        m0 = m1
    qv[(s, a)] = nows + LEARNING_RATE * (r + DISCOUNT_FACTOR * m0 - nows)

for i in range(500000):
    obs = env.reset()
    if i % 1000 == 0:
        print i
    for _ in range(5000):
        s = discretize(obs)
        s_0 = get(s, 0)
        nowa = 0
        s_1 = get(s, 1)
        if s_1 &gt; s_0:
            nowa = 1
        if random.random() &lt;= EPS:
            nowa = 1 - nowa
        obs, reward, done, info = env.step(nowa)
        s1 = discretize(obs)
        if done:
            reward = -10
        update(s, nowa, s1, reward)
        if done:
            break


for i_episode in range(1):
    obs = env.reset()
    for t in range(5000):
        env.render()
        s = discretize(obs)
        maxs = get(s, 0)
        maxa = 0
        nows = get(s, 1)
        if nows &gt; maxs:
            maxa = 1
        obs, reward, done, info = env.step(maxa)
        if done:
            print("Episode finished after {} timesteps".format(t+1))
            break

<h1>二、为什么用强化学习</h1>
<h2>（1）看一看混排</h2>
<p><img alt="" loading="lazy" src="/logbook/images/algorithm/df9673c29f6ab0381f23.png"/></p>
<p>做混排有几个难点</p>
<ul><li>
<p>数据异构：不同的数据包含不同的特征</p>
</li>
<li>
<p>目标不同：不同内容的各自优化目标不同，很难做统一的内容排序</p>
</li>
<li>
<p>运算量大：总的计算量高达业务数*每个业务的精排数量</p>
</li>
<li>
<p>内容的质量不同：点击率高的优质内容，比如高点击率的视频，会挤压低点击率的业务</p>
</li>
</ul><h2>（2）统一的点击率预估排序？</h2>
<p><img alt="" loading="lazy" src="/logbook/images/algorithm/02c7d61aa79c8a84b3ed.png"/></p>
<p>结论：视频是业务中点击率最高的，新闻是业务中点击率最低的，把点击率高的业务占比提高，点击率低的业务占比降低会提高整体的点击率，但不会提高整体点击数</p>
<h2>（3）强化学习的引入 - 优化长期收益</h2>
<ul><li>用户在推荐场景浏览可以建模成 Markov Progress</li>
<li>Agent是我们的推荐系统，Action是我们推荐了什么内容，Reward是用户的反馈信息，包括点击、负反馈、退出等</li>
<li>每次我们的推荐系统Agent采取某个Action，给用户推荐了内容，用户给到我们相应的反馈</li>
</ul><p><img alt="" loading="lazy" src="/logbook/images/algorithm/5ca3c9647340e8de7b31.png"/></p>
<h2>（4）强化学习的优势</h2>
<ul><li>为什么强化学习优于监督学习</li>
</ul><p>混排三路召回，mp，video，news合并</p>
<ul><li>Case</li>
</ul><p>mp，video，video（0，1，1）</p>
<p>video，mp，mp（1，0，0）</p>
<p>video，video，video（1，0，0）</p>
<ul><li>监督学习预测最优解是第三种</li>
</ul><p>选择点击率最大的</p>
<ul><li>强化学习预测最优解是第一种</li>
</ul><p>选择总收益最大的</p>

<h2>（2）Personal DQN</h2>
<p><img alt="" loading="lazy" src="/logbook/images/algorithm/fed846ac057fcaed225e.png"/></p>
<p>当用户的请求到来时会根据他之前的行为计算隐状态作为此次输入state的一部分，每次选择某个业务作为action，用户点击作为reward</p>
<h2>（3）离线评估 AUC？</h2>
<p>做算法，非常重要的一个环节就是做离线评估，传统的CTR预估用的就是AUC来评价</p>
<p><img alt="" loading="lazy" src="/logbook/images/algorithm/06384354f06d76740620.png"/></p>
<p>我们先看看传统AUC的意义，传统AUC的意义有两种</p>
<ul><li>
<p>假阳率和真阳率画出ROC曲线围成的面积表示了阈值移动情况下真阳假阳的表现</p>
</li>
<li>
<p>随机取一个正值和负值，正值的预估值大于负值预估值得概率，即 P(pred(a) &gt; pred(b) | y(a) &gt; y(b))</p>
</li>
</ul><p>利用第二种定义，我们扩展一下，于是我们定义我们新的AUC</p>
<ul><li>
<p>P(Q(a) &gt; Q(b) | sum reward(a) &gt; sum reward(b))</p>
</li>
</ul><p>为什么不像其他很多人一样利用一些模拟器的方式来做评价呢，很多实践表明，模拟器的方式有很大的偏置，这里新的AUC表征了实际数据的情况，优于其他一些利用模拟器而导致模型学偏</p>
<p><img alt="" loading="lazy" src="/logbook/images/algorithm/47d53a950d918c448db1.png"/></p>
<p>我们可以看到新的AUC更符合我们长期收益的定义，即，最大化总点击数</p>

<h2>（8）负反馈 Reward &amp; Focal loss</h2>
<p>我们可以把负反馈信息作为负的reward学到我们的模型里但是有一个问题，负反馈信息过于稀疏，负反馈占总展现的比例大概千分之一于是我们引入CV里的Focal loss做优化，对于easy case减小梯度权重，对于hard case加大权重，让稀疏的hard case能学得更好，最终使得负反馈率降低19%</p>
