<h3>1. 特征工程小科普</h3><p>什么是特征工程？特征工程主要用来解决机器学习的输入应该是什么的问题，换句话说就是考虑如何表述样本或背景知识的过程。特征工程是机器学习领域的重要内容，然而它也是很容易被忽视的一部分，人们拿到数据后总是迫不及待的去训练、预测，却往往忽视了对数据本身的审视。实际上这正是因为人们忽视了”语言”的表述与学习系统之间的紧密关系。如果”语言”的表述能够抓住问题的重要特征，那么学习系统可以以比较简单而又合理的方式产生问题的解，这也就是说要想愉快的玩转机器学习，先需要进行特征工程处理。</p>
<p>大量的实践也证明，数据的数量和质量其实对模型的预测效果和你即将获得的结论有着直接且巨大的影响。正如Pedro Domingos在《A Few Useful Things to Know about Machine Learning》所说：</p>
<blockquote>
<p>some machine learning projects succeed and some fail. What makes the difference? Easily the most important factor is the features used 。</p>
</blockquote>
<ul><li><h4>良好的特征意味着更强的适应性</h4><p>  不用再费力找到一个最优的模型了，在良好的特征数据上，即使选择一个“the wrong models”，你依然可以获得一个不错的结果。因此，你可以选择一个不复杂的模型，用更短的时间运行完毕，并且很容易的理解和维护它。这种体验真是棒极了！</p>
</li><li><h4>良好的特征带来更简单的模型</h4><p>  不用再辛苦的获取最优参数了，在良好的特征下，“the wrong parameters”依然能得到较好的结果。因为良好的特征能让你更靠近问题的本质，同时它们也成为问题本质的最好表达。</p>
</li><li><h4>良好的特征带来更好的结果</h4><p>   在模型一致的情况下，特征的好坏就成为了成功的关键。尤其对于许多数据分析的竞赛者，取胜的原因往往是把更多精力放在了特征工程上。</p>
</li></ul><p>因此，<strong>正确的机器学习打开方式应该是</strong>，首先采用特征工程，对你的数据进行构造、选择和评估，当获得了良好的特征后再进行通常的模型构建等过程。</p>

<h3>3. 特征转换</h3><p>特征转换过程是一个建立新特征的过程。通常需要花费大量时间来进行数据采样，并且需要重点考虑问题的表达形式和数据的组成结构。</p>
<h4>3.1 Scaler</h4><p>特征的归一化算法。在机器学习中很多模型属于数值敏感型，例如LR和SVM等，为了尽量减小数值对这类模型的影响，我们需要对特征的数值进行归一化操作。这样做的好处在于：</p>
<ol><li>加快模型的收敛速度</li><li>去除量纲</li><li>提升模型的效果</li></ol><p>良好的归一化，对于提高模型的准确度有着关键性的效果，而且能够降低模型的占用空间。</p>
<ul><li><p><strong>[模块构建]</strong></p>
<p>  Jarvis特征工程中的Scaler模块集成了两种归一化方式：最大最小值归一化（MinMaxScaler），标准化（StandardScaler）</p>
<ul><li><p><strong>MinMaxScaler算法</strong></p>
<p>  对特征数据进行统一的归一化处理，默认归一化后的特征数值范围在[0,1]，用户也可以指定归一化后的取值范围为[min,max]。计算公式为：</p>
<p> ((x−EMin)/(EMax−EMin))∗(max−min)+min((x-EMin)/(EMax-EMin))*(max-min)+min((x−EMin)/(EMax−EMin))∗(max−min)+min</p>
<p>  其中x表示需要归一化的特征值，EMin表示该特征下的最小值，EMax表示该特征下的最大值，min与max为用户设定的归一化后的数值范围。这里还考虑了特殊数据的情况：当某列特征的最大最小值相等时，该列所有数值归一化为0.5*(max - min) + min。</p>
</li><li><p><strong>StandardScaler算法</strong></p>
<p>  主要对特征进行标准化处理，原始特征数据通过该算法的转化将成为方差为1，均值为0的新的特征。计算公式为：</p>
<p> ((x−Mean)/Var)((x-Mean)/Var)((x−Mean)/Var)</p>
<p>  其中，Mean代表该特征的平均值，Var表示该特征的样本标准差。同样的，该模块考虑了以下特殊情况:</p>
<ol><li>如果Var为0，则x标准化后的结果直接为0.0</li><li>不需要均值化处理：此时算法只做方差处理，即：x/Var</li><li>不需要方差处理:x直接取值(x-Mean)</li></ol><p>为了方便，为用户提供了特征配置文件来指定某个特征的归一化方法。下面是一个该模块的JSON格式的特征配置文件样例</p>
<pre>{
  "minmax":[
    {
      "colStr": "1-2",
      "min": "0",
      "max":"1"
    },
    {
      "colStr":"5",
      "min":"-1",
      "max": "1"
     }
     ],
      "standard":[
     {
      "colStr": "3,6-7",
      "std": "true",
      "mean":"false"
     },
     {
      "colStr": "8,9",
      "std":"true",
      "mean":"true"
     }
     ]
}
</pre>
<p><strong>特征配置参数说明:</strong></p>
<ul><li>“minmax”和”standard”:分别代表了相应的归一化模块MinMaxScaler和StandardScaler</li><li>“colStr”:需要做相应处理的特征id,取值根据该特征在原始表的所在列，从0开始计数。多个特征可用”,”隔开，还可用”-“标识特征的起始到结束列，例如”1-20”表示第1列到第20列。</li><li>“min”:归一化后的最小值</li><li>“max”:归一化后的最大值</li><li>“std”:是否需要做方差的标准化</li><li>“mean”:是否需要做均值的标准化</li></ul></li></ul></li><li><p><strong>[关键技巧]</strong></p>
<ol><li><p>一次性计算所有特征的统计量</p>
<p> 通过以上两个公式，我们可以看到进行特征转换的关键在于获得每个特征对应的最大值、最小值或者平均值和样本标准差。当需要对多个特征进行上述的转换过程，同时这些特征对应的数据量又很大时，如何在较短时间内获得这四个统计量就成为了构建模型的关键。</p>
</li><li><p>分布式处理</p>
<p> 在Jarvis特征工程中，该模块采用spark平台中的treeAggregate聚合方式进行分布式计算，一次性计算出所有需要转换的特征的统计量，然后每个特征根据自己对应的统计量进行相应的转换即可。</p>
<blockquote>
<p>测试中发现对12个样本容量为亿级别的特征进行转换时，该模块的运行仅耗时22min。</p>
</blockquote>
</li></ol></li></ul><h4>3.2 Discrete</h4><p>特征的离散化算法。对特征离散化有很多好处：</p>
<ol><li>简化问题。这一点非常明显，对特征离散化不光能够有效避免数据中隐藏的缺陷，例如数据中存在的”极端”值往往导致了模型参数过高或过低。同时，对于树类的模型，离散化特征能简化算法对最优划分点的寻找，从而加快训练速度。</li><li>鲁棒性增强。按照一定规则对连续型特征进行离散，增加了输入数据的鲁棒性，从而提高了模型的泛化能力。</li></ol><ul><li><strong>[模块构建]</strong></li></ul><p>Jarvis特征工程中Discrete模块对特征数据进行离散化处理，离散方法包括等频和等值离散方式。等频离散法按照特征值从小到大的顺序将特征值划分到对应的桶中，每个桶中容纳的元素个数是相同的；等值离散法根据特征值中的最小值和最大值确定每个桶的划分边界，从而保证每个桶的划分宽度在数值上相等。<br/>使用Discrete模块需要对特征指明其离散化的类型等参数，下面是一个JSON格式的特征配置文件样例：</p>
<pre>{
    "feature": [
      {
        "id": "2",
        "discreteType": "equFre",
        "numBin": "3"
      },
      {
        "id": "5",
        "discreteType": "equVal",
        "numBin": "3",
        "min": "0",
        "max": "100"
       },
       {
        "id": "0",
        "discreteType": "equVal",
        "numBin": "2",
        "min":"-1"
      }
    ]
}
</pre>
<p>以上是对3个特征进行配置，特征配置之间的顺序没有要求，如果某些特征不需要离散配置，则不写在配置中。该配置文件中的”feature”不可更改，用户只需对如下参数进行修改即可:</p>
<p>特征配置参数:</p>
<ul><li>“id”:表示特征Id,注意该Id是输入数据中特征所在的列号，从0开始计数</li><li>“discreteType”:离散化的类型，”equFre”表示等频离散，”equVal”表示等值离散</li><li>“numBin”:离散化的桶数，需注意，在等频离散方法中，如果桶数设置过大，每个桶中的元素个数过少，导致离散边界中有重复的点，则出错</li><li>“min”:针对等值离散的配置，限定了特征值的最小值，如果特征值中有比这个值还小的则出错。如果没有需要可不填，同下面的”max”</li><li>“max”:针对等值离散的配置，限定了特征值的最大值，如果特征值中有比这个值还大的则出错，没有需要可不填</li></ul><ul><li><p><strong>[关键技巧]</strong></p>
<ol><li><p>避免不必要的计算<br/>避免不必要的任务流过程带来的运行时长，这一点尤其要注意。在加载数据并计算以及保存数据前，首先应该判断用户的等频或等值离散任务是否存在，例如模块既有对离散边界的保存，也有对离散化后数据的保存，如果输出路径仅有离散边界，那么模块就无需对数据进行离散化的过程。</p>
</li><li><p>使用参数限制特殊情况<br/>为了避免将数据中的异常值作为等值离散的极大值或极小值，特征配置中提供了对应的参数”min”,”max”来进行限制；同时”numBin”参数限制了等频离散法将相同特征值分到不同桶中的情况。</p>
</li><li><p>离散边界的计算<br/>模块采用了先根据原始数据获得每个特征的离散边界，然后根据离散边界划分每个特征值到对应的桶中的方法。其中等值离散需要自动识别数据中的最大值与最小值，同样的采用treeAggregate聚合函数一次性计算所有需要等值离散的特征，减小计算时长；等频离散采用了对每个特征值按照大小先排序然后再根据特征配置过滤出每个桶的离散边界的方式。</p>
</li><li><p>二分法离散数据<br/>获得离散边界并对原始数据进行离散化的时候，如何快速定位到每个原始特征值对应的桶呢？由于这里的离散边界都是有序存储，因此非常适合二分查找法，同时也比一般的顺序查找法更快速。</p>
<blockquote>
<p>经测试，运用以上技巧后，对12个样本容量为亿级别的特征进行离散化只需要0.5h。</p>
</blockquote>
</li></ol></li></ul><h4>3.3 TransformByGBDT</h4><p>一种基于GBDT模型的特征转换的算法。基于GBDT(Gradient Boosting Decision Tree)算法的特征转换不同于上述特征转换算法，它属于有监督的变换。使用GBDT做特征转换现已在业界有了广泛的应用，最常见的就是将GBDT特征转换的结果作为LR算法的输入。其主要的优点在于能自动发现多种有区分性的特征以及特征组合，省去了人工寻找特征或者进行特征组合的过程。下图是一个GBDT过程的例子</p>
<p><img alt="" loading="lazy" src="/logbook/images/deep-learning/b7daf4eabce98e4cd311.png"/></p>
<ul><li><strong>[模块构建]</strong></li></ul><p>TransformByGBDT算法是根据Tesla平台XGBoost模块的训练、预测结果进行特征转换的算法。TransformByGBDT算法的特征转换过程为：首先判断每个样本属于GBDT集成模型中每棵树的某个叶子节点，然后根据这一情况利用GBDT模型的所有叶子节点组合成该样本对应的特征。算法的特征最后以onehot的格式输出，其中1代表样本落入该叶子节点，0代表未落入该叶子节点。这里给出详细过程的参考论文<a href="https://pdfs.semanticscholar.org/daf9/ed5dc6c6bad5367d7fd8561527da30e9b8dd.pdf">《Practical Lessons from Predicting Clicks on Ads at 》</a>。</p>
<ul><li><p><strong>[关键技巧]</strong></p>
<ol><li>XGBoost的预测结果以分布式存储，因此，整个转换过程最好以分布式的方式进行，这样避免占用过大的内存，同时尽可能的保证了运行速度。</li><li>由于模型和预测结果以JSON格式存储，正确解析以及提取关键值就成为了关键。首先需要对模型进行解析，获得集成模型的叶子节点分布情况，然后识别每个样本预测结果中的叶子节点编号，并根据叶子节点分布转换化为对应的onehot编码。</li></ol></li></ul><h3>4. 特征选择</h3><p>特征选择过程就是指从一堆特征中选择出对建模有用的特征的过程。有时候数据中会存在与问题不相关的特征，或者有些特征与其他特征相比没有那么重要，甚至有时一些特征是冗余的，这都对建模没有太大作用，需要我们识别并剔除。当然这样做的好处也是显而易见的：</p>
<ol><li>增强泛化能力</li><li>提高模型的解释能力</li><li>提高计算效率，避免了维数灾难</li></ol><p>Jarvis特征工程中主要采用了过滤式的方式进行特征选择，这种方式通用性强，复杂度低，并且适合大规模计算。</p>
<h4>4.1 Information Based</h4><p>Information Based属于基于信息计算类的特征选择方法。通过信息度量有效的计算出每个特征的重要度，从而对特征进行有效的选择。</p>
<ul><li><strong>[模块构建]</strong></li></ul><p>Information Based模块是对目标列为二值类型的数据进行计算的模块，其中正例为1，负例为0。该模块总共包括基于信息类的4种算法：信息增益（Information Gain）、基尼系数（gini）、信息增益率（Information Gain Ratio）以及对称不确定性(Symmetry Uncertainly)，计算公式如下：</p>

<p>基尼系数公式：<br/><img alt="" loading="lazy" src="/logbook/images/deep-learning/faae402110fc84abfacf.png"/></p>
<p>信息增益率公式：<br/><img alt="" loading="lazy" src="/logbook/images/deep-learning/ccc64c6ba31d4c7c1392.png"/></p>
<p>对称不确定性公式：<br/><img alt="" loading="lazy" src="/logbook/images/deep-learning/83bcc2a0def0b6b9cbee.png"/><br/>其中H(X)与H(Y)为信息熵, IG(X/Y)为信息增益</p>
<ul><li><p><strong>[关键技巧]</strong></p>
<ol><li>同时统计所有特征的正、负样例分布<br/>当数据以列方式进行分布式存储时，同时获得所有特征的正负样例分布就成为了关键。在构建中，将每个特征在数组中的index作为特征的id编号，所有特征值与其id形成key-value的形式重新分布式储存，并以此计算正、负样例分布。这样做的好处就在于避免了不同特征值的个数过多造成内存溢出的情况，同时提高了算法效率。<blockquote>
<p>测试中发现，模块在千万数据量下运行时长仅5min。</p>
</blockquote>
</li><li>候选特征的指定<br/>不同于前面几种特征工程算法，这里没有特征配置，因此，提供灵活的方式来选择需要化为候选特征集的特征就非常必要了。模块在这里采用了解析字符串的方式获得每一个候选特征集的索引，并根据索引提取出对应的特征进行计算。 </li></ol></li></ul><h4>4.2 ChiSqSelector</h4><p>ChiSqSelector模块基于卡方独立性检验做特征选择。它主要计算应变量与特征之间的相对独立性，如果独立性较高，则特征与应变量之间的关系较弱，应该舍弃。反之，该特征对应变量有较强的影响，应该保留。</p>
<ul><li><strong>[模块构建]</strong></li></ul><p>特征选择过程将根据卡方独立性检验结果，将每个特征对应的卡方统计量按照从大到小的顺序进行排序，根据这一排序用户可指定选择的特征个数，否则系统将根据默认值提取前几个特征，这里默认值为50。如果实际特征个数小于用户指定的个数或者系统默认的个数，那么所有特征将会被选择。</p>
<ul><li><p><strong>[关键技巧]</strong></p>
<ol><li>以批处理方式统计<br/>模块主要使用了spark中的ChiSqTest进行卡方检验。这里简要总结下ChiSqTest的实现过程，ChiSqTest将划分的特征集以批处理的方式与应变量进行独立性检验。它首先统计了每一批特征的不同特征值在每种应变量下的个数，以此得到理论频数，然后再根据公式一一计算每个特征的卡方统计量以及对应的概率值P。这种批处理方式既满足计算效率的要求，又避免了内存溢出的情况。</li><li>针对类别性变量的计算<br/>卡方检验是专门针对类别型变量的，但如果数据是连续型数值，ChiSqTest将会把每个不同的连续型数值作为单独的一种类别进行计算。这种方式在进行统计时非常容易造成内存溢出，因此，ChiSqTest按分区检验了每个特征以及因变量所对应的不同特征值个数是否大于阈值的情况，如果大于则作为异常处理。实际上对于连续型数值，可以先对它们进行离散化处理，然后再进行卡方独立性检验。</li></ol></li></ul><h4>4.3 FeatureImpByGBDT</h4><p>FeatureImpByGBDT模块是一个基于XGBoost组件计算特征重要度的模块。通过用特征数据训练出集成模型从而判断特征的重要度。该模块提供了三种衡量特征重要度的指标：weight、gain以及cover。</p>
<ul><li>weight: 特征在所有树中出现的总次数</li><li>gain: 特征在所有树中出现对于模型的平均提升（Gini不纯度增益）</li><li><p>cover: 特征在所有树中平均覆盖的样本数</p>
</li><li><p><strong>[模块构建]</strong><br/>模块根据特征在集成树模型中出现的情况，一次性计算出了上述三种重要度指标，根据该指标不光可以判断特征在集成模型构建中的作用，同时还能从不同角度衡量特征的相对重要程度。</p>
</li><li><p><strong>[关键技巧]</strong><br/>  这里主要是对XGBoost模型的存储格式以及相关计算接口的了解，不再详述。</p>
</li></ul><h3>5. 特征评估</h3><p>特征评估主要对特征进行搜索和评估，从而找到最有益于分析问题的特征。搜索过程可以从一个空的特征子集开始，也可以从整个特征集开始。在Jarvis特征工程中，采用了前者，每次通过搜索和评估添加一个或者多个特征来扩充特征空间。特征评估的优点主要在于避免维数灾难，提高计算效率，有助于分析模型与变量之间的关系。</p>
<h4>5.1 Correlation</h4><p>Correlation模块提供了pearson和spearman两种相关系数的计算方法来获得连续型数值特征之间的相关性，并以此对特征进行评估。为了尽可能满足计算需求，该模块将特征分为两种：原始特征和新加入的特征。因此特征相关性的计算也分为两种：一是对新加入的特征进行两两之间的相关性计算，结果为一个对角矩阵，每个对角矩阵的元素为两两特征之间的相关性系数，该值越大，说明这两个特征相关性越强；二是将新加入的特征与原始特征分别进行相关性计算,注意：当某列特征的方差为0时，与该特征计算的相关性值为NaN。</p>
<ul><li><p><strong>[模块构建]</strong></p>
<p>  在模块中，如果没有指定新加入的特征列，则模块不进行任何计算，也不输出任何结果；如果只指定了新加入的特征列，没有指定原始表中的特征列，则仅计算新加入特征两两之间的相关性；如果既指定了新加入的特征列，又指定了原始表中的特征列，则模块不光会计算新加入的特征两两之间的相关性，同时还会将新加入的特征分别与原始特征列计算相关性。下面举几个例子说明上述情况：</p>
<ul><li><p><strong>只指定了新加入的特征列</strong><br/>输出为新加入特征两两之间的相关性。例如新加入特征列为1,2,3，则输出格式为：</p>
<pre># 相关性系数输出样例
X 1 2 3
1 1.0 0.15 0.25 
2 0.15 1.0 0.38 
3 0.25 0.38 1.0
</pre><p>上面的数据显示总共有三个特征进行两两之间的相关性计算。第一行与第一列分别显示新加入特征的Id(X可忽略)，除此之外的其他元素分别为新特征两两之间的相关性系数。各元素之间以空格隔开。</p>
</li><li><p><strong>新特征与原始特征均被指定</strong><br/>输出为两种相关性矩阵的合并，这两种矩阵分别是新特征两两之间的相关性矩阵和新特征与原始特征的相关性矩阵。例如新加入特征为1,2,3，原始特征列为4,5,6,7，则输出格式为：</p>
<pre># 相关性系数输出样例
X 1 2 3 4 5 6 7
1 1.0 0.15 0.25 0.57 0.15 0.25 0.02
2 0.15 1.0 0.38 0.15 0.11 0.38 0.49
3 0.25 0.38 1.0 0.25 0.38 0.03 0.21
</pre><p>上面的数据中第一行为新加入特征与原始特征的Id(X可忽略)，第一列为新加入特征Id，除此之外的其他元素为新加入特征两两之间或新特征与原始特征之间的相关性系数。</p>
</li></ul></li><li><p><strong>[关键技巧]</strong></p>
<ol><li>一对多的相关性计算<br/>spark mllib包中虽然提供了相关性计算的方法，但该方法只包括多个特征之间的相关性计算，没有实现某个单独的特征与其他特征之间的相关性计算方法。也就是说，spark mllib包只能计算新加入特征的两两相关性计算，没有提供新特征与原始特征之间的相关性计算。因此，模块中还提供了这一部分的实现。为了提高计算效率，首先采用treeaggregate的方法一次性计算出所有特征的平均值和标准方差，然后根据相关性计算公式进行计算。期间为了提升计算协方差的效率，采用了treereduce的方法，一次性得到了所有的相关性结果。<blockquote>
<p>经测试，亿级别的样本在“spearman”的方式下耗时1hour，在“pearson”方式下耗时仅0.5hour。</p>
</blockquote>
</li></ol></li></ul><h4>5.2 MultualInformation</h4><p>MultualInformation是一种对类别型数值特征进行相关性计算的模块。特征之间的相关系数越大说明特征相关性越强。其中互信息的原理与计算公式可<a href="https://zh.wikipedia.org/wiki/Mutual_Information">参考</a>。同Correlation模块，MultualInformation模块的相关性计算也分为两种：一是对新加入的特征进行两两之间的相关性计算，结果为一个对角矩阵，每个对角矩阵中非对角线的元素为特征两两之间的互信息，对角线元素为该特征的信息熵；二是将新加入的特征与原始表中的特征分别进行互信息计算。</p>
<ul><li><strong>[模块构建]</strong></li></ul><p>MultualInformation模块的构建和结果表示与Correlation基本一致，此处不再详述。</p>
<ul><li><p><strong>[关键技巧]</strong></p>
<ol><li><p>使用更适合分布式计算的公式<br/>互信息的计算公式经过推导后有很多种，例如：</p>
<blockquote>
<p>I(X;Y)<br/>= H(X) - H(X|Y)<br/>= H(X) + H(Y) - H(X,Y)</p>
</blockquote>
<p>上述公式虽然都能计算出X与Y之间的互信息，但是从计算的角度，尤其是分布式计算而言，条件熵H(X|Y)就不如联合熵H(X,Y)的计算更简便快速。因此模块中使用了后者进行互信息的计算。</p>
<blockquote>
<p>测试模块在千万容量的样本下，耗时仅为8min。</p>
</blockquote>
</li></ol></li></ul><h3>6. 特征工程的结果展示</h3><p>当你使用如上特征工程完成了相关的计算后，如何以最简单、直接的方式查看、比较以及分析结果就成为一个关键，例如单纯的看特征选择和特征评估的结果很难让人快速对特征进行判断。基于此，Jarvis特征工程专门在tesla平台发布了矩阵结果的查看功能，具体的tesla样例可参考。下面就是一个矩阵结果的展示效果。</p>
