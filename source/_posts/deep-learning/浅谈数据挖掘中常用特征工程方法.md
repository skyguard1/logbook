<p>特征处理在挖掘的过程中必不可少，但一般却很少被提及。在一个挖掘项目中，大家最先关注的是采用了什么模型、什么算法，来实现，而并非对哪些特征做了细节的处理，使得同样的算法达到了更好的效果。Quora 上有人表示：</p>
<p>Actually the success of all Machine Learning algorithms depends on how you present the data.<br/> -- <a href="https://www.quora.com/What-are-some-general-tips-on-feature-selection-and-engineering-that-every-data-scientist-should-know">What are some general tips on feature selection and engineering that every data scientist should know?</a></p>
<p>也表达了相同的观点。本文列举了一些在实际工作中会采用的特征工程方法，由于特征工程内容繁多，应该可以写本书，本文是小菜鸟的一点总结，疏漏也是很多，请各位达人拍砖指教！</p>

<h1>特征初选</h1>
<p>特征，可以理解成模型的属性，在我们常见的业务挖掘中，通常会有这么几类：</p>
<p>•             用户特征（比如用户的性别、年龄、学历等画像特征）</p>
<p>•             目标特征（比如某个 QQ 头像挂件）</p>
<p>•             环境特征（比如时间，操作槽位等）</p>
<p>这些特征中，有些特征对模型比较重要，而有些可能是冗余的特征，选择合适的特征对减少模型训练时间、提高模型的效果，有积极的影响。</p>
<p>最初的特征选择，可以来自产品业务的经验。例如在某些付费产品的模型中，就可以加入用户 vip 状态的特征。常见业务，可以使用本身的数据流水中的维度作为特征，而有少数挖掘的场景，没有流水操作数据，则需要将其他可以反应挖掘对象特征的数据作为模型的属性。在一次对一个 QQ 号码包用户身份识别的挖掘场景中，由于缺少充分的挖掘目标的数据，就添加了用户加入的群数据作为特征进行挖掘。</p>
<h1>特征预处理</h1>
<p>特征预处理，一般也就是清洗和打分了。有些特征值会出现一些异常值，例如，年龄特征，为空/负值/超过150 等。还有些特征，本身的范围应该是 0 - 100 之间，但可能上报的数据岔了，特征值变成了 10000, 这些都需要在特征入库时清洗掉。</p>
<h1>特征构造</h1>
<p>预处理好特征后，就可以对特征进行构造，以便模型算法能够更好的使用。最常用的构造方法包括：标准化、正规化、和离散化。一些其他的特征构造方法，在遇到实际的算法或者业务场景时，可以叠加使用。</p>
<p>1.      标准化（Standardization）。比如有一组特征，<img alt="图示" loading="lazy" src="/logbook/images/deep-learning/fdb2ca066d6799de1387.png"/>, <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/3e3d320fc72d42367644.png"/> 是长，单位是 m; <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/317e91c6715879ecc100.png"/> 是宽，单位是 cm. 这两个特征都可以比较、加减，但是如果没有标准化的化，混在一起搞就不合适了，所以一般用下面的方式进行标准化（<img alt="图示" loading="lazy" src="/logbook/images/deep-learning/931e3cbb904b81f0bff1.png"/> 是均值，<img alt="图示" loading="lazy" src="/logbook/images/deep-learning/894ebb911fc6185c9d02.png"/> 是标准差。）：<br/> <br/> </p>
<p><img alt="图示" loading="lazy" src="/logbook/images/deep-learning/c5c40a6a130c2e1afc1d.png"/></p>
<p>2.          正规化（Normalization）。比如，个性装扮的特征用向量 <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/cf30f7fb37d4feefebb1.png"/> 表示，<img alt="图示" loading="lazy" src="/logbook/images/deep-learning/8d0880b56d11fec3b6f7.png"/> 是使用第 <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/7538256c8b425462c7ab.png"/> 个装扮的人数, 这时候可以用 <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/80f641f01a970d10953d.png"/>，来表示这个特征的分布、消除装扮总数对特征的影响。<br/> <br/> </p>
<p>3.          本地特征抽取（Extraction of local features）。这就是，用其他的算法，把特定领域的知识，转化为特征。比如文本处理中常用的TF-IDF方法。<br/> <br/> </p>
<p>4.          特征离散化（Feature discretization）。有些算法，例如 LR, 对连续的特征处理不是很好，这时候，就可以对连续的特征进行离散化处理，比如，1003g 就可以离散成 1kg 和 3g. 而且如果这样做的话，对理解数据也有好处。<br/> <br/> </p>
<p>5.          线性和非线性空间嵌入法（Linear and non-linear space embedding methods）。有时候数据的维度非常高，就需要给数据降维，并且尽可能多的保留数据的信息，比如用 PCA 或者 MDS, 这样的话，可能对数据可视化也有帮助。<br/> <br/> </p>
<p>6.          非线性扩张（Non-linear expansions）。这个跟上面降维是相反的，因为有时候问题就是很复杂，并且直接用那些特征不能取得很好的效果，就把一个特征，<img alt="图示" loading="lazy" src="/logbook/images/deep-learning/fd6171dc68b7ff03b474.png"/>, 扩张成 <img alt="图示" loading="lazy" src="/logbook/images/deep-learning/9e40a8a71dbb4bba48db.png"/>.<br/> <br/> </p>
<p>7.          信号增强（Signal enhancement）。这个业务上，不常用。通常图片处理的算法里用的比较多。</p>
<h1>特征选择</h1>
<p>特征选择，初看上去是为了选择最相关、最有益的特征，但是特征选择对减小数据量、提高模型准确度以及理解数据方面都会有好处。特征选择通常有 3 种方式：过滤(filter)、封装(wrapper)和嵌入(Embedded)。</p>
<p>过滤(filter)通常用的就是用算法给特征排序，常用的算法包括：计算相关系数和经典校验统计（T检验、F-检验、卡方检验等）算法。在 Spark 中，可以直接使用 Statistics.chiSqTest(vec) api 来对数据进行卡方检验。</p>
<p>封装(wrapper)就是利用机器学习的方法，来给特征进行预测打分，然后再来选择特征。例如  就采用了 GBDT 来进行特征选择和离散[1]。这个方法，在我厂的也有应用[2]。</p>
<p>嵌入(Embedded)通常就是，在训练的过程中，再进行特征选择。这个可以在一些特定的算法中，对算法进行优化的时候用。</p>
<h1>特征库建立以及特征监控</h1>
<p><img alt="图示" loading="lazy" src="/logbook/images/deep-learning/f1cf583c2c604874ca77.png"/></p>
<p>在我们组建立的特征库中，用户画像特征包括一些用户基础特征，如年龄、性别，以及一些挖掘结果的特征，如学历、是否大学生、收入情况等组成，业务特征由对接的各项业务提供，经人工选择、预处理后，入库到预处理特征库，然后再根据不同的特征，采用不同的算法来对特征构造后入库到构造特征库。在建模时，可以通过读取特征配置表来灵活的对模型配置不同的特征子集。并且，我们对构造特征建立了监控来保证模型能够顺利的例行化训练。</p>
