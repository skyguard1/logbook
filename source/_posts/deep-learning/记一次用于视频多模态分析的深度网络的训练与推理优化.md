<p>近年来，深度学习的应用领域越来越广，早已从图像识别领域扩展到语音、文本、视频等领域。目前本人正在进行视频多模态分析的工作，使用的正是深度网络。相比传统的图像和文本领域，视频分析需要的数据量很大，网络的训练和推理也非常耗时。本文记录的是一次针对视频分析的多模态网络的训练与推理加速的方法，供大家参考。</p>
<p> </p>
<h3>1、原始网络</h3>
<p>我进行的视频分析工作，是以镜头为单位进行的。神经网络的输入是镜头的特征，输出是每个镜头的标签。算法的大致流程如下。</p>
<p>先是预处理工作，对视频做镜头分割，得到一系列镜头，保存每个镜头的视频。</p>
<p>然后进行特征提取。第一，从镜头视频中提取镜头的中间帧，送入一个特征提取网络（如 ResNet34）得到一维向量，作为该镜头的 cv 特征。第二，从镜头视频中提取镜头的全量音频波形，送入另一个特征提取网络，得到一维向量，作为该镜头的 audio 特征。</p>
<p>接下来是网络部分。在得到上述基于镜头的原始特征后，特征需要按照 batch_size x seq_len x shot_num 的顺序组织起来，送入网络。其中 seq_len 是一个 batch 中送入网络的镜头数，shot_num 表示当前镜头的邻域长度。如 shot_num 等于 4 时，第 i 号镜头的输入是第 i-1，i，i+1 和 i+2 号镜头特征的拼接。也就是说，一个镜头的特征，不仅包含当前镜头，还包含邻域镜头。上述过程可借助图 1 进行理解。</p>
<p><img alt="" loading="lazy" src="/logbook/images/deep-learning/cb918813b469fa13444c.png"/></p>
<p>图 1</p>
<p>这个版本的网络中，输入是镜头的特征。每个镜头的特征可以事先提取好，保存于硬盘。在网络训练时根据镜头编号从硬盘读取需要的特征。我们注意到，同一份特征会被读取多次。由于特征维度较低，占用空间较小，所以反复读取硬盘不会造成很大的开销。</p>
<p> </p>
<h3>2、骨干网络参与训练</h3>
<p>为了提升网络能力，我们考虑将 cv 和 audio 两路特征提取网络加入视频分析网络中参与训练。如图 2 所示。一方面，我们读取的数据，从离线提取的特征，变成镜头的中间帧，和镜头的音频。我们在加载完中间帧后，还需要做一些如减均值除以标准差的工作。在加载完音频后，可能还需要做频谱计算。我们使用的深度学习框架是 PyTorch，这部分工作是在 DataSet 的 __getitem__ 函数中完成的。另一方面，深度网络的输入从特征变成图像或者语音信号，我们需要对这些信号送入各自的骨干网络，完成特征提取，再送入原来的视频分析网络。这部分工作是在 Module 的 forward 函数中完成的。</p>
<p> <img alt="" loading="lazy" src="/logbook/images/deep-learning/c97f07112fb24e6697a3.png"/></p>
<p>图 2</p>
<p>我们注意到，由于存在重复镜头，__getitem__ 函数和 forward 函数就会需要做大量的重复数据加载和重复计算。<strong>为了减少数据读取次数，减少重复计算，我们需要对加载和计算进行去重。</strong></p>
<p> </p>
<h3>3、优化方法</h3>
<p>由于 cv 和 audio 两个分支的操作是类似的，优化操作只描述 cv 分支的部分。</p>
<p>我们很容易注意到，每个镜头的帧文件的文件名是互不相同的，可以用文件名作为去重的标记。</p>
<p>在 DataSet 的 __getitem__ 函数中，我们先按照 seq_len x shot_num 的要求取出当前 batch 需要的文件名，再进行 unique 操作，获取当前 batch 的净文件名，读取这些文件，进行预处理，得到处理过的帧，再按照网络输入的格式要求，重排成 seq_len x shot_num 的形式。如图 3 所示。这样一来，加载帧和预处理的复杂度，就从 seq_len x shot_num下降为 seq_len + shot_num。（<strong>注意，去重计算的复杂度实际是 seq_len + shot_num - 1，为表述简洁，去掉 - 1</strong>）</p>
<p><img alt="" loading="lazy" src="/logbook/images/deep-learning/01b1e4816667a4b97fa1.png"/></p>
<p>图 3</p>
<p>在 Module 的 forward 函数中，我们也进行类似的去重计算工作。为了进行去重，DataSet 的 __getitem__ 函数，不仅要返回预处理后图片的 tensor，还要反回按照 seq_len x shot_num 维度进行排列的字符串。这样，在 forward 函数中，对每个 batch，我们先对文件名进行一次去重，并且记录去重后的文件名列表与原来 seq_len x shot_num 格式排列下的下标对应关系，然后从seq_len x shot_num 格式排列的预处理图片 tensor 中取出去重后的 tensor list，送入骨干网络提取特征，然后再将特征组合成 seq_len x shot_num 格式排列，再送入原来的视频分析网络。如图 4 所示。去重操作，同样将特征提取的复杂度，从 seq_len x shot_num 下降为 seq_len + shot_num。</p>
<p><img alt="" loading="lazy" src="/logbook/images/deep-learning/f6e1658061f4b48dc69c.png"/></p>
<p>图 4</p>
<p>我们的网络训练是单机多卡 DataParallel 模式下运行的。在训练和调试过程中，我们发现，DataSet 的 __getitem__ 函数如果返回 seq_len x shot_num 的二维字符串 list，PyTorch 不会像高维 tensor 那样，把高维字符串按照卡进行分配。例如，全局 batch size 等于 16，GPU 数量等于 8 的情况下，我们期望每张卡获得的字符串是 2 x seq_len x shot_num，但实际每张卡得到的字符串是16 x seq_len x shot_num 的总量。</p>
<p>为了解决这个问题，有两种方法。第一种方法是改写 PyTorch 中的一个 scatter 函数，如 PyTorch 论坛所述。</p>
<p><a href="https://discuss.pytorch.org/t/is-there-a-way-to-set-a-custom-scatter-function-for-dataparallel/56751">https://discuss.pytorch.org/t/is-there-a-way-to-set-a-custom-scatter-function-for-dataparallel/56751</a></p>
<p><a href="https://discuss.pytorch.org/t/dataparallel-chunking-for-a-list-of-3d-tensors/15962">https://discuss.pytorch.org/t/dataparallel-chunking-for-a-list-of-3d-tensors/15962</a></p>
<p>另一种方法，是修改 DataSet 的 __getitem__ 函数。在函数最后将高维字符串转换成整型 tensor。因为每个字符可以用 ord 函数对应成一个非负整数，文件名字符串长度有上限，所以这个方法是可行的。DataSet 的 __getitem__ 函数返回 seq_len x shot_num x max_str_len 维度的整型 tensor 表示文件名。在 Module 的 forward 函数执行开始，需要对字符串整型 tensor 调用 chr 函数恢复成字符串。</p>
<p> </p>
<h3>4、优化结果</h3>
<p>经过试验发现，上述去重方法能够有效降低 audio 分支 backbone 参与训练情况下的训练时间。在我们现有训练环境下，如果仅 audio 分支 backbone 参与训练，去重操作能够将一个 epoch 的训练时间从超过 4 小时下降到不到一个半小时。我们采用的是 seq_len = 32，shot_num = 4，理论加速比是 (32 x 4) / (32 + 3) = 3.66。实际加速与理论加速相当。</p>
<p>如果仅有 cv 分支的 backbone 参与训练，去重操作的加速较少，一个 epoch 仅能加速一两分钟，训练时间都是十几分钟数量级。这有两方面的原因，一方面，图片文件相比原始音频 wav 文件小很多，图片加载耗时少，另一方面，语音可能需要复杂的 stft 计算等预处理，耗时较多，而图片的减均值除以标准差计算很快。</p>
<p>去重算法还能节省显存资源。仅有 cv 分支的 backbone 参与训练的情况下，计算不去重，一张卡消耗的显存超过 9 G，去重后，一张卡显存消耗不到 7G。</p>
